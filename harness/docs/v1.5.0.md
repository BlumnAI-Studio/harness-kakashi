**날짜**: 2026-05-08

## 변경 요약

[[hoshimori|🌟 호시모리(별지기, Hoshimori, 星守)]]를 새 에이전트로 영입했다.
나루토 세계관의 [[naruto-worldview|Hoshigakure(星隠れの里, 별의 마을)]] 출신 별 수호자 캐릭터로 매핑된다.

이 에이전트는 옵시디언(Obsidian) vault로 이 저장소를 열었을 때 모든 문서가 별자리로 연결되어 보이도록 위키링크 그래프를 가꾸고 유지한다.

---

## 영입 사유 — Zettelkasten의 AI 시대 재조명

### 선행 조사

영입 전 다음 두 가지를 조사했다:

1. **Obsidian의 Zettelkasten 기법이 AI 시대에 재조명받는 이유**
   - Karpathy의 LLM Wiki 패턴(`ingest / query / lint`)
   - 핵심 결론: 지식베이스 가치는 **링크 밀도 ∝ 가치** (노트 수가 아님)
   - 노트 1000개 + 링크 50개 < 노트 100개 + 링크 500개

2. **Anthropic의 위키태그 / 지식 그래프 기법**
   - *Effective context engineering for AI agents* (2025)
   - Knowledge Graph Memory MCP — multi-hop 질의, edge-level citation
   - XML 태그 / Markdown 헤더 / 위키링크의 3종 구획화

3. **A-Mem (NeurIPS 2025)** — Zettelkasten 원리를 LLM 메모리에 이식한 연구
   - LinkGenerator 4 전략: entity co-occurrence / semantic similarity / tag overlap / LLM relationship reasoning

조사 정전: [[zettelkasten-llm-era|📚 Zettelkasten · 위키태그 정전]]

### 결론 — 별지기가 필요했다

기존 하네스에는:
- [[tamer|tamer]] (정원지기) — 메타 에이전트
- [[sage-deming|sage-deming]] (현자) — 사상 적용
- 차크라 카카시 (그림자) — 토큰 감사

…가 있었지만, **지식 그래프 자체를 가꾸는 keeper**가 없었다.
링크 밀도가 노트 가치를 결정한다면, 그 밀도를 유지할 전담 에이전트가 필요하다 — 그것이 호시모리다.

## 베이스 룰 — 향후 자동 적용

향후 다음 시점에 호시모리는 **사용자 명시 호출 없이도** 작동한다:

| 시점 | 동작 |
|------|------|
| 새 `.md` 파일이 적용 범위(README/harness/docs)에 추가됨 | 신규 별 footer 부착 + 인근 별 footer 갱신 |
| 기존 `.md` 본문에 다른 문서 참조 추가 | 본문 위키링크 변환 + 양쪽 footer 갱신 |
| `harness.config.json` 의 agents/engine 변경 | 새 에이전트/엔진의 footer 부착 |
| 신규 버전 히스토리 (`harness/docs/vX.Y.Z.md`) 작성 | 버전 별과 관련 변경 별 사이 잇기 |

이 규칙은 다음 위치에 등록되어 있다:
- [[hoshimori|harness/agents/hoshimori.md]] §7 "자동 발동 규칙"
- `harness/harness.config.json` `keepers.hoshimori.alwaysOn: true`
- 본 v1.5.0 문서 (사유 추적용)

자동 발동을 끄려면: `harness.config.json` → `keepers.hoshimori.alwaysOn: false`

## 호환성

- 기존 에이전트, 트리거, 명령은 모두 그대로 동작한다
- 호시모리는 코드를 점검하지 않으므로 기존 점검 워크플로우와 충돌하지 않는다
- 위키링크 추가는 markdown 표준 호환 — 기존 markdown 렌더러(GitHub, VS Code)는 무시하거나 자연스럽게 표시한다
- Obsidian으로 vault를 열면 그래프 뷰가 점등된다

Major가 아닌 이유: 기존 에이전트/트리거/명령이 모두 그대로 동작한다.
Patch가 아닌 이유: 새 에이전트 타입(`keeper`)과 새 자동 발동 메커니즘을 도입했다.
