# v1.6.0 — 지도지기 치즈모리 영입 (harness-view + GitHub Pages)

**날짜**: 2026-05-08
**유형**: Minor (새 keeper 에이전트 + 정적 사이트 도입)

---

## 변경 요약

[[chizumori|🗺️ 치즈모리(地図守, Chizumori)]]를 두 번째 keeper로 영입했다.
나루토 세계관의 [[naruto-worldview|Konohagakure(木ノ葉隠れの里, 나뭇잎 마을)]] 호카게 타워 기록실 출신 마을 지도 수호자로 매핑된다.

이 영입과 함께 `Home/harness-view/` 정적 사이트가 신설되었고, GitHub Pages 배포 워크플로우(`.github/workflows/pages.yml`)가 활성화되었다.

---

## 영입 사유 — 마을 지도가 필요했다

지난 [[v1.5.0]]에서 [[hoshimori|호시모리(별지기)]]가 영입되어 옵시디언 vault에서 별자리(지식 그래프)를 잇기 시작했다. 그러나 vault는 **내부자**의 도구다.

마을 외부의 행인(GitHub 방문자, 미래의 사용자)이 정원의 모습을 보려면 별도의 지도가 필요하다 — 그것이 **harness-view**다.

[[hoshimori]]가 노트와 노트 사이의 **별자리**를 잇는 keeper라면, [[chizumori]]는 정원 자체의 **지도**를 그려 외부에 공개하는 keeper다. 둘은 keeper 계열의 자매 관계다.

---

## 두 가지 역할 (Dual Role)

치즈모리는 명확히 분리된 두 역을 가진다:

### 役 1 — 뷰동기화 (View Sync)

`Home/harness-view/scripts/sync-view.js` 실행 → 다음을 생성:

| 산출물 | 경로 | 내용 |
|---|---|---|
| `_meta.json` | `indexes/` | 빌드 시각, 소요 시간, 카운트 |
| `agents.json` | `indexes/` | 14+1개 에이전트 매니페스트 |
| `knowledge.json` | `indexes/` | knowledge/ 매니페스트 (lore/methodology 포함) |
| `engine.json` | `indexes/` | engine/ 매니페스트 |
| `docs.json` | `indexes/` | 버전 히스토리 + 컨트리뷰터 |
| `logs.json` | `indexes/` | 활동 로그 카테고리별 집계 |
| `worldview-graph.json` | `indexes/` | 나루토 세계관 인물·술법 추출 |
| `pdsa-insight.json` | `data/` | **PDSA 4축 동적 집계** |

### 役 2 — 뷰 퍼블리싱 (View Publishing)

`.github/workflows/pages.yml` 트리거:
- `doc-v*` 태그 푸시 → 자동 배포
- 수동 트리거 (`workflow_dispatch`)

CI에서 sync-view.js 실행 → 저장소 전체를 GitHub Pages artifact로 업로드 → 배포.

## 정적 vs 동적 분리 원칙 (CRITICAL)

치즈모리의 핵심 원칙:

### 정적 (참조 only, 복제 금지)
- `harness/agents/*.md`, `harness/knowledge/**/*.md`, `harness/engine/*.md`, `harness/docs/*.md`, `harness/logs/**/*.md`
- 뷰 코드는 `loadMd('harness/agents/foo.md')` 호출로 **`../../`** 상대 경로에서 직접 fetch
- `indexes/`나 `data/`에 본문 직렬화 절대 금지
- 단일 정전(Single Canon) 보장

### 동적 (sync 단계에서만 생성)
- `Home/harness-view/indexes/*.json` — 매니페스트, git 메타, 시계열
- `Home/harness-view/data/pdsa-insight.json` — PDSA 4축 집계 ([[sage-deming]] 사상 빌려와서 집계만)
- 모든 동적 산출물은 `sync-view.js` 한 번 실행으로 재생성 가능 (멱등성)

> **인간 손글씨와의 분리**: `data/news.json`은 사람이 직접 쓰는 narrative — sync가 덮어쓰지 않음. `data/pdsa-insight.json`은 sync가 생성 — 손으로 안 건드림.

## 사용 방법

```bash
node Home/harness-view/scripts/sync-view.js
# 그 후 정적 서버로 Home/ 디렉토리 서빙 (Python: python -m http.server)
```

### 카카시 하네스 명령으로 호출
```
/harness-kakashi-creator 뷰동기화
/harness-kakashi-creator 하네스뷰 퍼블리싱
```

### 정식 릴리스 배포
```bash
git tag doc-v1.6.0
git push --tags
# GitHub Actions가 자동으로 sync + 배포
```

## 호환성

- 기존 에이전트, 트리거, 명령은 모두 그대로 동작
- `harness/` 트리는 단일 정전(Single Canon)으로 유지 — 뷰는 fetch만, 복제하지 않음
- [[hoshimori|호시모리]]의 별자리 footer는 뷰 렌더링과 충돌하지 않음 (markdown 호환)
- GitHub Pages 배포는 `doc-v*` 태그가 있을 때만 실행 — 일상 푸시는 영향 없음

Major가 아닌 이유: 기존 에이전트/트리거가 모두 그대로 동작.
Patch가 아닌 이유: 새 keeper(`chizumori`)와 정적 사이트, CI/CD 워크플로우를 도입.
